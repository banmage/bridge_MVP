# 06 测试与验收计划（联网 MVP 一期）

**版本**: v1.1  
**状态**: 评审通过（2026-11-01），CR-006 回归通过（2026-11-02）  
**关联**: [`01-需求规格说明书.md`](./01-需求规格说明书.md)、[`05-评审记录.md`](./05-评审记录.md)

## 1. 测试目标

1. 验证 28 条功能需求与 10 条非功能需求；
2. 证明服务端权威、视角隔离、非法动作零状态变更；
3. 证明断线重连、超时托管、多窗口互踢、重启恢复可用；
4. 证明单人 MVP 无回归；
5. 为发布门禁提供可重复执行的证据。

## 2. 测试分层

| 层级 | 范围 | 工具/位置 | 执行频率 |
|------|------|-----------|----------|
| L1 单元 | 法律、计分、规则、AI、赛程、人格、工具函数 | Vitest；`src/core`、`src/engine`、`src/ai`、`shared` | 每次提交 |
| L2 服务端集成 | MatchEngine、RoomManager、投影、持久化、房间快照/恢复、协议分发 | Vitest node；`server/__tests__/` | 每次提交 |
| L3 客户端状态 | 重连、终局竞态、多窗口互踢、复盘缓存 | Vitest happy-dom；`src/store/online.test.ts` | 每次提交 |

## 5. 验收用例

### US1 建房开赛

| 步骤 | 预期 |
|------|------|
| 输入昵称 → 创建 18 副/贴点制 → 选南家 | 获得 6 位房间码，进入房间，自己为房主 |
| 北/东/西设为机器人 | 座位面板同步显示人格 |
| 点击开始 | 第 1 副开始，四人收到各自快照 |
| 未填满时开始 | 返回“还有空座位” |
| 完成 18 副 | 状态 `finished`，成绩页显示总计 |

### US2 AI 人格

| 步骤 | 预期 |
|------|------|
| 设置名字/风险/体系/约定 | 房间内所有人可见 |
| 开启负加倍并触发 | 叫牌记录带提醒文本 |
| 随机度 0 + 固定 seed | 重放叫牌/出牌一致 |
| 非法人格字段 | 回退默认，不崩溃 |

### US3 双真人

| 步骤 | 预期 |
|------|------|
| A 建房坐南，北机器人；B 加入坐东，西机器人 | 双方座位同步 |
| 开赛后查看快照 | 只看到自己手牌；明手首攻后公开 |
| B 断开 30 秒后重连 | 回到东家，手牌/轮次恢复 |
| B 断开超过 60 秒 | 东家由机器人接管，比赛继续 |
| 非当前行动者出牌 | 返回错误，状态不变 |

### US4 实时对局

| 步骤 | 预期 |
|------|------|
| 叫牌到 3NT | 正确判定庄家/明手/首攻 |
| 首攻落地 | 明手摊牌；仅庄家可代打 |
| 跟牌点击错误花色 | 服务端拒绝并提示 |
| 四家 Pass | 流局，双方 0 分 |
| 完成 13 墩 | 结算并广播 |

### US5 成绩与复盘

| 步骤 | 预期 |
|------|------|
| 完成 6 副后打开成绩 | 每副定约/结果/得分/IMP/点数 |
| 比赛结束查询历史 | 服务端已落盘，重启后仍可查 |
| 打开任意一副回放 | 四手牌、叫牌、逐墩与记录一致 |
| MP 模式查看某副 | 显示 7 桌对照场与百分比 |

### US6 大厅

| 步骤 | 预期 |
|------|------|
| 建房后刷新页面 | 自动回到未结束房间（服务端仍在） |
| 打开最近比赛 | 可进入详情 |
| 开赛后重启服务端，再刷新页面 | 用原身份回到原座位与当前副，比赛继续 |

## 6. 非功能测试

| 项 | 方法 | 通过标准 |
|----|------|----------|
| 视角隔离 | `view.test.ts` + 手工四视角 | 0 泄漏 |
| 非法动作 | `match.test.ts` | 100% 拒绝且状态不变 |
| 确定性 | 固定 seed + 随机度 0 | 动作序列一致 |
| 重连 | 手工断网/关标签 | 30s 内恢复 |
| 托管 | 手工/自动化时钟 | 60s 后 AI 接管 |
| 多窗口 | 两个标签页同身份 | 旧窗口停止重连，无循环 |
| 重启恢复 | 开赛后重启进程 + 自动化快照测试 | 房间/座位/当前副恢复；无人重连超时托管 |
| 性能 | 局域网 4 连接 | 广播 P95 < 50ms |
| 容量 | 脚本建 200 房间 | 一期目标，非硬门槛 |
| 安全 | 报文/视图检查 | 无 token/seed/他人手牌 |

## 7. 回归策略

- **每次提交**：L1–L4 全量。
- **发布前**：L1–L5 全量 + 手工冒烟 + 生产模式健康检查。
- **回归重点**：`/solo`、法律/计分、视角投影、重连/托管、持久化查询。
- **缺陷修复**：先写失败测试，再修复，最后全量回归。

## 8. 缺陷管理

| 级别 | 定义 | 处理 |
|------|------|------|
| P0 | 数据泄漏、状态被非法修改、无法开赛 | 立即修复，阻塞发布 |
| P1 | 核心流程不可用、断线无法恢复、比赛卡死 | 发布前修复 |
| P2 | 体验/提示/边界问题 | 可排期，记录 |
| P3 | 文案/样式/优化 | 后续迭代 |

缺陷记录至少包含：复现步骤、期望/实际、影响范围、根因、修复提交、回归测试。
