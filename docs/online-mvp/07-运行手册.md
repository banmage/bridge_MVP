# 07 运行手册（联网 MVP 一期）

**版本**: v1.1  
**状态**: 评审通过（2026-11-01），CR-006 补充（2026-11-02）  
**适用**: 单进程 Node 服务 + 静态前端 + 文件系统记录

## 1. 运行前检查

| 项 | 要求 |
|----|------|
| Node.js | 24.x（建议），最低满足 `tsx` 与 ES2022 |
| 内存 | ≥ 512MB（一期 200 房间目标建议 1GB） |
| 磁盘 | 记录目录可写；按比赛量预留 |
| 网络 | 客户端可访问 HTTP 与 WebSocket |
| 端口 | 默认 8787（可用 `PORT` 覆盖） |

## 2. 安装与启动

```bash
npm ci

# 开发
npm run dev:all        # Vite 5173 + 服务 8787

# 生产
npm run build          # 产出 dist/
npm start              # 同端口托管 dist/、/api、/ws
```

启动成功日志：

```text
[bridge] server listening on http://0.0.0.0:8787 (ws: /ws, api: /api)
```

若存在进行中房间快照，启动时还会输出：

```text
[bridge] restored N in-progress room(s)
```

## 3. 环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `PORT` | `8787` | HTTP + WebSocket 端口 |
| `HOST` | `0.0.0.0` | 监听地址；仅本机可设 `127.0.0.1` |
| `AI_DELAY_MS` | `700` | 机器人每次动作延迟（毫秒） |
| `AUTO_NEXT_MS` | `10000` | 结算后自动开下一副等待时间 |
| `BOT_TAKEOVER_MS` | `60000` | 开赛后断线托管宽限期；`0` 关闭 |
| `MATCH_DATA_DIR` | `server/data/matches` | 比赛记录目录（绝对/相对路径） |
| `ROOM_DATA_DIR` | `server/data/rooms` | 进行中房间快照目录（绝对/相对路径） |

> 修改环境变量后需重启进程。`BOT_TAKEOVER_MS` 应大于客户端重连预期时间（建议 ≥ 30s）。

## 4. 健康检查

```bash
curl -s http://127.0.0.1:8787/api/health | jq
```

返回示例：

```json
{
  "ok": true,
  "version": "0.1.0",
  "protocol": 1,
  "rooms": 3,
  "uptimeSec": 120
}
```

判读：

- `ok=false` 或请求失败：进程未启动/端口错误/反向代理异常；
- `rooms` 持续增长且不下降：可能存在房间泄漏或未结束对局堆积；
- `protocol` 与客户端不一致：前后端版本不匹配。

## 5. 数据与备份

- 正式记录：`server/data/matches/<matchId>.json`（仅**完整结束**的比赛）；
- 进行中快照：`server/data/rooms/<roomCode>.json`（开赛后持续更新，比赛结束写入正式记录后删除）；
- 写入方式：临时文件 + rename，避免半截文件；
- 备份：定期复制 `MATCH_DATA_DIR` 与 `ROOM_DATA_DIR`；恢复时停止进程 → 放回文件 → 启动；
- 清理：按保留策略删除旧 JSON；不要在进程运行时删除正在写的文件；
- 快照损坏会被启动流程跳过，不影响其他房间；确认无需恢复后可手工删除对应 JSON。

## 6. 反向代理

Nginx 示例：

```nginx
server {
  listen 80;
  server_name bridge.example.com;

  location /ws {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
  }

  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
  }
}
```

要求：

- `/ws` 必须支持 WebSocket upgrade；
- SPA 路由（`/room/*`、`/matches/*`）回退到 `index.html`（Node 已内置 fallback，代理直接转发即可）；
- 生产建议启用 HTTPS，客户端会自动使用 `wss://`；
- 代理层可加连接数/速率限制，防止滥用。

## 7. 监控建议

一期仅有控制台日志与健康检查。建议至少监控：

| 指标 | 来源 | 告警建议 |
|------|------|----------|
| 进程存活 | 进程管理器/health | 连续 2 次失败 |
| HTTP 5xx | 反向代理日志 | 5 分钟内 > 1% |
| WebSocket 连接数 | 代理/进程指标 | 突增/突降 |
| 房间数 | `/api/health.rooms` | 持续增长不下降 |
| 磁盘使用 | 系统 | > 80% |
| 记录写入失败 | 应用日志 | 出现即告警 |

日志建议字段：`level/time/event/roomCode/playerId/errorCode`；**不要记录 token、完整手牌**。

## 8. 常见故障处理

### 8.1 前端连不上 `/ws`

1. 确认 `GET /api/health` 正常；
2. 检查反向代理 `/ws` upgrade 配置；
3. 检查 `PORT/HOST` 与代理目标；
4. 浏览器控制台看是否 `wss://` 证书错误。

### 8.2 房间卡住不推进

1. 查看该房间是否有人断线；
2. 等待 `BOT_TAKEOVER_MS` 后应自动托管；
3. 若仍未推进，检查服务端日志是否有机器人异常；
4. 应急：让房内玩家主动离开触发立即托管；也可重启进程，进行中房间会从快照恢复。

### 8.3 重连后回不到座位

1. 确认浏览器 `localStorage` 的 `bridge.identity.v1` 未被清除；
2. 确认断线时间未超过 `BOT_TAKEOVER_MS`（超时后座位已托管）；
3. 确认房间未结束/未解散；
4. 查看服务端是否返回 `AUTH_FAILED`/`ROOM_NOT_FOUND`/`WRONG_PHASE`。

### 8.4 多窗口互相踢下线

- 预期行为：新窗口生效，旧窗口收到 `DUPLICATE_SESSION` 后停止重连并提示；
- 若旧窗口仍反复重连，检查客户端版本是否为最新（CR-001 修复）。

### 8.5 记录查不到

1. 比赛是否**完整结束**（未结束不落盘）；
2. 检查 `MATCH_DATA_DIR` 与权限；
3. 检查日志是否有落盘失败（失败不阻断对局，下次结算/查询可重试）；
4. 用 `GET /api/matches` 确认摘要是否存在。

### 8.6 进程重启

- 开赛后未结束的房间会从 `ROOM_DATA_DIR` 快照恢复，客户端用原身份重连即可回到原座位与当前副；
- 恢复后所有真人先视为离线，`BOT_TAKEOVER_MS` 倒计时重新开始；无人重连的座位超时后由机器人接管；
- 已结束比赛记录保留；结束且已写入正式记录的房间不会重复恢复；
- 若日志出现 `restored N in-progress room(s)`，说明恢复成功；
- 若客户端收到 `ROOM_NOT_FOUND`，检查房间是否已结束、快照是否被清理，或 `ROOM_DATA_DIR` 权限/路径是否正确。

## 9. 发布与回滚

### 发布

1. 备份当前 `dist/`、`package-lock.json`、`MATCH_DATA_DIR`；
2. `npm ci && npm run build`；
3. 运行测试与冒烟；
4. 切换进程/重启；
5. 健康检查 + 观察 30 分钟。

### 回滚

1. 停止新版本进程；
2. 恢复上一版本代码/`dist/` 与依赖；
3. 恢复数据目录（如发生不兼容写入）；
4. 启动并健康检查；
5. 记录回滚原因与影响。

## 10. 容量与限制

- 单进程、房间状态内存态 + 本地快照（仅支持单实例恢复，多实例需共享存储）；
- 一期目标 ≥ 200 并发房间（未做硬性压测）；
- 单房间 4 连接；
- 全量快照单帧 < 10KB；
- WebSocket 单帧上限 64KB；
- 聊天保留最近 50 条，单条 200 字。

## 11. 安全注意事项

- 生产必须使用 HTTPS/WSS；
- 不要暴露 `MATCH_DATA_DIR` 到公网静态目录；
- 不要在日志中输出 token、完整手牌；
- 定期更新依赖并审计 `npm audit`；
- 反向代理层增加连接/速率限制；
- 一期无账号体系，token 泄露等同于身份泄露，需提示用户不要在公共设备保留。
