# 01 需求规格说明书（联网 MVP 一期）

**版本**: v1.2  
**状态**: Baselined（2026-11-01 需求评审通过，2026-11-02 CR-006/007/008 补充）  
**负责人**: 技术负责人（banmage）  
**关联基线**: [`spec.md`](../../specs/001-online-pair-game/spec.md)

## 1. 背景与目标

现有项目是单机人机桥牌 MVP（南家 + 3 机器人）。本期把同一套法律、叫牌规则与 AI 搬到
Node 服务端，形成**服务端权威**的联网对局，支持：

- 1 名真人 + 3 个可配置 AI；
- 2 名真人各自带 AI 同伴同桌对抗；
- 12 / 18 / 24 副比赛；
- 双人赛（MP 对照场）与贴点制两种计分；
- 断线重连、超时托管、成绩统计与逐副复盘。

**成功定义**：两名真人 + 两名机器人可无刷新完成 12 副比赛，断线后可恢复；所有动作由服务端校验，
任何客户端都看不到未公开的他人手牌；比赛记录可落盘并可复盘。

## 2. 范围

### 2.1 本期范围（In Scope）

| 编号 | 能力 | 说明 |
|------|------|------|
| S1 | 大厅与房间 | 昵称、创建/加入、6 位邀请码、最近比赛 |
| S2 | 座位编排 | 真人/AI/空位，房主管理，开赛后冻结 |
| S3 | AI 人格 | 名字、风险、体系、约定、随机度 |
| S4 | 权威对局 | 叫牌、加倍/再加倍、出牌、明手、赢墩、结算 |
| S5 | 两种计分 | MP 对照场、贴点制 |
| S6 | 连接韧性 | 自动重连、断线保留座位、超时托管（保留原身份收回权）、多窗口互踢 |
| S7 | 记录与复盘 | 逐副记录、整场落盘、HTTP 查询、单副回放 |
| S8 | 单人兼容 | 原功能迁移到 `/solo`，既有测试保持通过 |
| S9 | 人类辅助 | 叫品解释与推荐（不自动提交）、推荐出牌箭头；不读取视角外信息 |

### 2.2 本期不做（Out of Scope）

- 账号密码、第三方登录、跨设备身份迁移；
- 公开观战、旁观者聊天、观众席；
- 队式赛、全场赛、跨房间配对、排行榜；
- 数据库、分布式房间、水平扩容；
- 比赛时限/超时判负、声称/摊牌、DDS 双明手；
- 移动端专门适配（沿用桌面布局）。

> **需求评审决定 R-01**：一期“房主旁观”不单独实现，房主必须占一座；公开观战列入二期。
> 原先 `spec.md` 澄清项中的歧义已按此口径修正。

## 3. 角色与术语

| 角色 | 职责/权限 |
|------|-----------|
| 玩家（真人） | 创建/加入房间、选座、比赛动作、聊天、查看成绩 |
| 房主 | 玩家的全部能力 + 开赛前管理座位/配置 + 开赛 |
| 机器人 | 由服务端调度，使用所属人格与同一套动作校验 |
| 服务端 | 唯一权威：发牌、校验、结算、视角投影、落盘 |
| 客户端 | 只发送意图、渲染服务端快照，不推导权威状态 |

术语：`Room` 房间、`Seat` 座位、`Board` 一副牌、`Match` 一场比赛、`MP` 比赛分、
`HCP-Points` 贴点制、`View` 按玩家裁剪后的快照。

## 5. 功能需求

### 5.1 房间与身份

| ID | 需求 | 验收要点 |
|----|------|----------|
| FR-001 | 仅凭昵称创建设备级身份 `playerId + token` | 刷新后身份不变；无密码 |
| FR-002 | 创建房间，生成 6 位 `[A-Z0-9]` 房间码，选择 12/18/24 副与计分模式 | 非法副数/模式被拒绝 |
| FR-003 | 房主可把任意座位设为自己/空位/机器人 | 机器人人格可编辑 |
| FR-004 | 真人可用房间码加入并选空座，变化实时同步 | 座位冲突返回 `SEAT_TAKEN` |
| FR-005 | 四座占满才可开赛；开赛后座位与配置冻结 | 未满返回 `SEATS_NOT_FULL` |
| FR-006 | 同一 `playerId + token` 断线重连恢复座位、手牌、轮次 | 重连后快照一致 |
| FR-007 | 真人主动离开或断线超时后由机器人接管 | 默认宽限 60 秒；超时托管保留收回权，原身份重连自动收回，主动离开则放弃 |
| FR-027 | 同一身份只允许一个活动连接 | 新连接生效，旧连接停止重连并提示 |

### 5.2 机器人人格

| ID | 需求 | 验收要点 |
|----|------|----------|
| FR-008 | 人格字段：名字、风险、体系、约定、随机度 | 非法值回退默认；体系缺省为精确 |
| FR-009 | 人格只影响动作选择，不改变合法性 | 任何人格都不能产生非法动作 |
| FR-010 | 使用约定叫品时生成提醒并随叫牌广播 | 叫牌记录含 `alerted/alertText` |
| FR-011 | 机器人由服务端调度，延迟可配置 | `AI_DELAY_MS` 生效，期间不可抢占 |

### 5.3 对局

| ID | 需求 | 验收要点 |
|----|------|----------|
| FR-012 | 按 16 副轮转表生成庄家/局况，按副数截取 | 12/18/24 副均正确 |
| FR-013 | 服务端为每副生成并保存 `seed`，可复现 | 同种子重放动作一致 |
| FR-014 | 服务端校验叫牌合法性 | 层级/加倍资格/轮次 |
| FR-015 | 服务端校验出牌合法性并公开明手 | 跟牌义务、首攻后摊牌 |
| FR-016 | 只允许庄家占用者代打明手 | 明手本人不能直接出牌 |
| FR-017 | 每副按标准复式计分；流局双方 0 分 | 与 `core/scoring` 一致 |
| FR-018 | 支持 MP 与贴点制两种计分 | MP 7 桌对照场；贴点复用现有公式 |
| FR-019 | 每副结算广播，全部副数完成后结束比赛 | 终局状态 `finished` |
| FR-029 | 为真人提供叫品解释/推荐与推荐出牌，仅辅助不代打 | 推荐不自动提交；只用自己/已公开手牌；服务端仍做最终校验 |
| FR-030 | 真人可主动托管自己的座位，由 AI 代叫/代打；可随时解除 | 座位与手牌仍归本人；托管状态写入快照 |
| FR-031 | 只剩唯一合法出牌时自动打出，不等待操作 | 仍需展示上一张牌满 `PLAY_DISPLAY_MS` |
| FR-032 | 房间解散、连接异常、动作被拒绝等提示同时写入聊天并标记“系统” | 顶部 toast 与聊天均可见；不与玩家发言混淆 |
| FR-033 | 每方（南北/东西）使用统一叫牌体系，缺省精确 | 修改一方机器人体系时同方同伴自动同步；开赛引擎按方取体系 |

### 5.4 记录、统计与视角

| ID | 需求 | 验收要点 |
|----|------|----------|
| FR-020 | 每副记录 seed、庄家、局况、四手牌、叫牌、出牌、计分 | 记录完整可复盘 |
| FR-021 | 比赛结束后 JSON 原子落盘，HTTP 可查 | 重启后仍可查询 |
| FR-022 | 成绩页展示逐副明细、累计、MP%、胜负 | 合计与逐副一致 |
| FR-023 | 单副复盘展示四手牌、叫牌表、逐墩出牌 | 与记录一致 |
| FR-024 | 按接收者视角裁剪快照 | 不见他人手牌/种子/token |
| FR-025 | 不向客户端下发隐藏信息 | token/seed/未公开手牌 |
| FR-026 | 保留 `/solo` 单人功能与既有测试 | 既有测试全绿 |
| FR-028 | 开赛后未结束房间原子写快照，进程重启后恢复房间/座位/当前副；结束后删除快照并写正式记录 | 重启后客户端原身份重连回到原座位与当前副，已结束房间不重复恢复 |

## 7. 约束与假设

- 单服务进程；房间状态在内存并持续写入进行中快照，比赛记录落盘；进程重启会恢复未结束房间。
- 网络时延按 < 200ms 设计；全量快照优先，单帧 < 10KB。
- 对照场统一“正常风险 + 精确体系 + 随机度 0”。
- 比赛不设时限；断线托管默认 60 秒，可通过 `BOT_TAKEOVER_MS` 调整或关闭（0）。
- 一期房主必须占座；公开观战二期实现。

## 8. 验收标准

| ID | 标准 |
|----|------|
| SC-001 | 单人 3 机器人 2 分钟内完成建房到第 1 副开叫 |
| SC-002 | 两名真人 + 两名机器人完成 12 副无刷新；1 次断线重连成功 |
| SC-003 | 逐副 IMP 之和与总计误差为 0；MP 百分比可复算 |
| SC-004 | 视角裁剪 0 泄漏（自动化断言） |
| SC-005 | 非法动作 100% 拒绝且状态不变 |
| SC-006 | 同 seed 重放，AI 叫牌/出牌完全一致 |
| SC-007 | 既有单人测试保持通过，`/solo` 行为不变 |
| SC-008 | 服务端重启后进行中房间可恢复，客户端原身份重连回到原座位与当前副；无人重连座位超时托管 |
| SC-009 | 超时托管后原身份重连可自动收回座位（重启后仍有效），主动离开则不可收回 |
| SC-010 | 人类辅助只预选/高亮叫品与推荐牌，不自动提交；不读取视角外手牌 |

## 10. 变更记录

| 变更单 | 内容 | 结论 |
|--------|------|------|
| CR-001 | 多标签页互踢导致自动重连循环 | 客户端收到 `DUPLICATE_SESSION` 后停止重连并提示 |
| CR-002 | 开赛后断线无超时托管，可能卡住比赛 | 增加 `BOT_TAKEOVER_MS`（默认 60s）与房主转移 |
| CR-003 | 房间已解散时客户端保留失效状态 | `ROOM_NOT_FOUND` 时清空房间与复盘缓存 |
| CR-004 | 文档与实现的环境变量/脚本不一致 | 统一为 `dev:server`、`MATCH_DATA_DIR`、`AI_DELAY_MS`、`AUTO_NEXT_MS`、`BOT_TAKEOVER_MS` |
| CR-006 | 进程重启丢失进行中房间 | 增加 `roomSnapshot.ts` 与 `ROOM_DATA_DIR`；启动时恢复房间并续跑 AI/下一副 |
| CR-007 | 断线超时被托管的座位无法由原玩家收回 | 记录 `takeovers`（座位→原身份）并写入快照；原身份重连自动收回，主动离开放弃；提示条支持手动「收回座位」 |
| CR-008 | 联网牌桌缺少单人模式已有的人类辅助 | 叫牌卡按规则库预选推荐并悬停解释；叫牌表悬停解释历史叫品；轮到人类出牌时闪烁箭头标出推荐合法牌 |
| CR-009 | 推荐箭头样式不统一、唯一合法牌仍需点击、系统提示易错过、缺少主动托管与每方体系约束 | 推荐复用座位闪烁箭头；唯一合法牌自动打出；提示写入聊天；新增托管按钮；体系按方统一并默认精确；放大叫牌/按钮字体与手牌 |
