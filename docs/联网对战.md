# 联网对战说明（一期）

本文件说明 `specs/001-online-pair-game/` 一期联网玩法的入口、运行方式与部署要点；
规则引擎、贴点公式等仍以 [`帮助文档.md`](./帮助文档.md) 与 `README.md` 为准。

## 一、入口与流程

| 路由 | 用途 |
|------|------|
| `/` | 大厅：昵称、创建房间、邀请码加入、最近比赛 |
| `/room/:code` | 房间：选座、机器人配置、开赛、牌桌、成绩与复盘 |
| `/solo` | 原单人模式（南家 + 3 机器人） |
| `/matches` | 历史比赛列表 |
| `/matches/:id` | 比赛详情与逐副复盘 |

1. 房主创建房间时选择 **12 / 18 / 24 副** 和计分模式（双人赛 MP / 贴点制）；
2. 房主占一座，其余座位可设为机器人或留空等待真人；
3. 真人用邀请码加入并选择空座；四座填满后房主开赛；
4. 每副结算后展示成绩，等待 `AUTO_NEXT_MS` 自动开下一副，也可手动继续；
5. 全部副数打完后生成比赛结果，可逐副复盘。

## 二、身份与断线重连

- 浏览器首次访问会生成 `playerId` 与 `token`，保存在 `localStorage`；
- WebSocket 断开后客户端自动重连，并用同一身份发送 `hello`，服务端恢复原座位；
- 未开赛时离开可回到大厅重新入座；开赛后主动离开立即由机器人接管该座位；
- 开赛后断线超过 `BOT_TAKEOVER_MS`（默认 60 秒）仍未重连，座位由机器人接管，比赛继续；
  超时托管保留原身份收回权：用同一身份重连会自动收回座位，也可在牌桌提示条点「收回座位」；主动离开则放弃；
- 同一身份打开多个窗口时以最新连接为准，旧窗口断开并停止自动重连；
- 若清空浏览器存储，原座位无法证明归属，只能以新身份重新加入。

## 三、权威与视角

- 服务端是唯一权威：叫牌、出牌、开赛、座位与配置变更均经服务端校验，非法动作不改变状态；
- 每个连接收到的是按 `playerId` 裁剪后的 `RoomView`：
  - 只包含自己的手牌；
  - 明手在首攻后摊开；
  - 结算前不会下发其他三家的手牌；
  - 不下发 token 与发牌种子。
- 客户端只发送意图（`bid` / `play` 等），不直接修改对局状态。

### 人类辅助

- 叫牌卡按当前体系推荐一个叫品并预选，悬停可看规则解释；**不会自动提交**，仍需点「确认」；
- 叫牌过程中悬停历史叫品可查看其含义；
- 轮到自己（或自己代打明手）出牌时，金色箭头标出系统推荐的合法牌；
- 牌桌按自己的座位旋转：自己始终在正下方、同伴在正上方，左右手与中央出牌区同步旋转；
- 聊天固定在牌桌左下角；叫品、历史叫牌与推荐出牌的说明统一通过悬停浮层显示；
- 辅助只使用自己的手牌与已公开的明手牌，由客户端复用规则引擎/出牌 AI 计算，不改变服务端权威判定。

## 四、机器人人格

每个机器人座位可配置：

- **风险**：保守 / 正常 / 激进（映射到叫牌、打牌风格参数）；
- **体系**：精确叫牌法 / 自然叫牌法；
- **约定**：强无将、负加倍、弱二、斯台曼、转移叫；
- **随机度**：`0..1`，`0` 时完全确定、可复现。

机器人使用与真人相同的动作校验路径，由服务端按 `AI_DELAY_MS` 调度。

## 五、计分

- **双人赛（MP）**：每副以同一副牌模拟 7 桌机器人对照场，将本桌 NS 得分换算为 `0..100` 的 MP 百分比；
- **贴点制**：复用单人模式的贴点公式，逐副累计为 NS / EW 点数。

逐副的 IMP、点数、MP 百分比、大牌点与对照场结果都会进入比赛记录。

## 六、比赛记录与查询

比赛完整结束后写入 `server/data/matches/<matchId>.json`（原子写，目录可用 `MATCH_DATA_DIR` 覆盖）。
开赛后未结束的房间会写入 `server/data/rooms/<roomCode>.json`（可用 `ROOM_DATA_DIR` 覆盖）；
进程重启时自动恢复，客户端用原身份重连即可回到原座位与牌局。

| 接口 | 说明 |
|------|------|
| `GET /api/health` | 版本、协议版本、房间数、运行时长 |
| `GET /api/match-schedule` | 16 副复式轮转表 |
| `GET /api/matches?limit=10` | 最近比赛摘要 |
| `GET /api/matches/:id` | 单场完整记录（四手牌、叫牌、出牌、计分） |
| `GET /api/players/:playerId/matches` | 某玩家的比赛 |

> 完整结束的比赛写入正式记录；进行中的对局另有服务端快照，重启后可恢复。

## 七、本地开发

```bash
npm install
npm run dev:all      # Vite(5173) + 对局服务(8787)
```

Vite 已把 `/ws`（WebSocket）与 `/api` 代理到 `8787`，浏览器访问 `http://localhost:5173/` 即可。

分别启动：

```bash
npm run dev:server   # 仅服务端
npm run dev          # 仅前端
```

## 八、部署

```bash
npm ci
npm run build        # 产出 dist/
npm start            # 同端口托管 dist/、/api、/ws
```

环境变量：

| 变量 | 默认 | 说明 |
|------|------|------|
| `PORT` | `8787` | HTTP + WebSocket 端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `AI_DELAY_MS` | `700` | 机器人动作延迟 |
| `AUTO_NEXT_MS` | `10000` | 结算后自动开下一副等待时间 |
| `BOT_TAKEOVER_MS` | `60000` | 开赛后断线托管宽限期；`0` 关闭 |
| `MATCH_DATA_DIR` | `server/data/matches` | 比赛记录目录 |
| `ROOM_DATA_DIR` | `server/data/rooms` | 进行中房间快照目录 |

反向代理要求：

- `/ws` 必须支持 WebSocket upgrade，并转发到同一 Node 进程；
- SPA 路由（`/room/*`、`/matches/*`）回退到 `index.html`；
- 房间状态保存在内存中，并持续写入进行中快照；进程重启会恢复未结束对局，
  已结束比赛记录不受影响。

Nginx 片段示例：

```nginx
server {
  listen 80;
  server_name bridge.example.com;

  location /ws {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
  }

  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
  }
}
```

## 九、常见问题

- **前端连不上 `/ws`**：确认服务端已启动，且 Vite 代理或反向代理指向正确端口。
- **重连后回到大厅**：`localStorage` 中的身份被清除，或房间已结束/不存在。
- **多窗口互相踢下线**：同一身份以最新窗口为准，旧窗口会断开并停止重连，属预期行为。
- **掉线太久座位变成机器人**：默认超过 `BOT_TAKEOVER_MS`（60 秒）未重连会托管；用同一身份重连会自动收回，
  也可点提示条「收回座位」；主动离开会放弃收回权。可调大宽限期或设为 0 关闭托管。
- **MP 百分比不可比**：对照场由每场比赛的 `seedBase` 决定，不同比赛之间不可直接比较。
- **刷新后比赛记录为空**：记录只在整场结束后落盘，进行中的对局不会写入磁盘。
